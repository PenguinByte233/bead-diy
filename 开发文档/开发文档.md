# 珠串 DIY · 开发文档

> 版本：v0.1.0
> 相关文档：需求与产品方向见同仓库的 [`规划.md`](./规划.md)

## 1. 项目概述

「珠串 DIY」是一个适配手机浏览器的在线手串搭配工具。用户在页面上方的圆形手串预览区实时查看搭配效果，从页面下方的素材区点击珠子即可添加到手串中；支持点按移除、按住拖动排序、撤销与清空，最终可将设计效果发送给店主作为定制依据。

当前为第一版（v0.1.0），目标是快速验证交互与展示效果，采用**本地静态数据 + SVG 伪 3D 渲染**，不依赖后端。

## 4. 数据模型

类型定义集中在 `src/types.ts`，核心思想是区分「素材目录项」与「手串上的实例」：

```ts
// 素材目录项（可被重复添加到手串）
interface BeadType {
  id: string
  name: string
  category: string          // 对应 BeadCategory.id
  material: string          // 材质中文名
  color: string             // 主色（hex），用于 SVG 渲染
  price?: number            // 参考单价（第一版暂不展示，预留）
  gloss?: 'high' | 'matte' | 'metallic'  // 光泽类型
}

// 手串上的一颗珠子实例（同一素材可出现多次）
interface BeadInstance extends BeadType {
  instanceId: string        // 唯一实例 id，如 inst-1
}

// 素材分类
interface BeadCategory {
  id: string
  label: string
}
```

**设计要点**：`BeadType` 是「目录」，`BeadInstance` 是「实例」。同一颗「白水晶」可能被添加到手串多次，因此用 `instanceId` 区分，删除/排序都按 `instanceId` 定位。

素材数据在 `src/data/beads.ts`，当前内置 4 类共 15 种珠子：

| 分类 | 珠子 |
| --- | --- |
| 水晶（crystal） | 白水晶、紫水晶、粉水晶、海蓝宝、绿幽灵 |
| 玉石（jade） | 白玉、翡翠、红玛瑙、黑曜石 |
| 木质（wood） | 檀木、花梨木、乌木 |
| 金属（metal） | 黄金、纯银、黄铜 |

## 5. 架构与状态管理

采用**无全局状态库、单组件状态提升**的简单架构：

- `App.tsx` 是唯一的状态持有者，管理两块状态：
  - `bracelet: BeadInstance[]` —— 手串上的珠子实例列表（顺序即排列顺序）
  - `history: BeadInstance[][]` —— 历史快照栈，用于撤销
- 子组件通过 props 接收数据与回调，不自行持有业务状态：
  - `Bracelet` 只负责渲染与手势，向上回调 `onRemove` / `onMove` / `onDragStart`
  - `BeadPalette` 只负责分类筛选展示，向上回调 `onAdd`

**状态操作**（`App.tsx`）：

| 操作 | 实现 | 是否记历史 |
| --- | --- | --- |
| 添加 | `addBead` → `commit([...bracelet, makeInstance(bead)])` | 是 |
| 删除 | `removeBead` → 按 `instanceId` 过滤 | 是 |
| 清空 | `clearAll` → `commit([])` | 是（仅当非空） |
| 排序 | `moveBead` → 取出后按目标槽位插入 | 否（拖动开始时记一次） |
| 撤销 | `undo` → 弹出历史栈顶部快照 | — |

`commit(next)` 会在应用新状态前先把当前 `bracelet` 压入 `history`，从而保证「撤销」能回到操作前状态。拖动排序比较特殊：`moveBead` 不逐次记历史（否则拖动过程中会产生大量快照），改为在拖动真正开始时（`dragStart`）记录一次快照。

## 6. 渲染原理：SVG 伪 3D 珠子

珠子不是真实图片或 3D 模型，而是用 SVG 的**径向渐变 + 高光点 + 描边**模拟立体感，实现在 `BeadGlyph.tsx`：

1. **径向渐变**：`radialGradient` 的圆心偏移到左上（`cx=0.35, cy=0.3`），从提亮的中心色过渡到压暗的边缘色，形成球体明暗。
2. **深色描边**：`stroke` 使用压暗 55% 的颜色，勾勒轮廓。
3. **左上高光点**：一个白色半透明小圆，模拟光源反射。

光泽类型 `gloss` 通过一组明暗/高光参数区分材质：

```ts
const highlight =
  gloss === 'matte'
    ? { light: 0.3, dark: 0.35, spot: 0.35 }   // 哑光：对比弱
    : gloss === 'metallic'
      ? { light: 0.7, dark: 0.55, spot: 0.7 }   // 金属：对比强、高光亮
      : { light: 0.5, dark: 0.4, spot: 0.6 }    // 高光（默认）
```

**重要实现细节**：每个 `<radialGradient>` 需要一个全局唯一的 `id`，否则不同珠子会互相覆盖渐变。因此 `BeadGlyph` 接收 `gradientId` 参数，由调用方传入唯一值：

- 素材区预览：`palette-${bead.id}`
- 手串实例：`bracelet-${bead.instanceId}`

颜色工具在 `utils/color.ts`，实现 `lighten`（向白提亮）和 `darken`（向黑压暗），支持 3 位/6 位 hex。

实拍珠子优先走 `<image>` 渲染：透明底 PNG 周围通常有大量留白，直接铺满会显得珠子比槽位小、之间出现空隙。因此每颗珠子在 `beads.ts` 里配有 `imageFit`（`{ w, h, cx, cy, r }`，主体中心 + 半径，图像像素），`BeadGlyph` 据此按 `r / imageFit.r` 缩放、把主体中心对齐圆心，让珠子填满槽位。新增珠子图片时需同时补上该参数（可用脚本量出非透明像素的包围盒得出）。

## 7. 几何计算（`utils/geometry.ts`）

手串布局由两个纯函数决定：

- **`beadPositions(count, cx, cy, radius)`**：将 `count` 颗珠子沿圆形均匀分布，角度从顶部（-90°）开始顺时针排列，返回每颗珠子圆心的 `{x, y}` 数组。
- **`beadRadius(count, braceletRadius)`**：以「满编 10 颗」为上限——10 颗时珠子恰好相切（无间隙），少于 10 颗保持满尺寸（间隙自然变大），超过 10 颗则缩小半径挤下下一颗；半径取下限 4px 避免过小。

`Bracelet.tsx` 中相关常量：

```ts
const SIZE = 320                 // SVG viewBox 尺寸
const CENTER = SIZE / 2          // 圆心 (160, 160)
const BRACELET_RADIUS = SIZE * 0.35  // 手串半径 112，保证 10 颗满编时珠子不超出 viewBox
const DRAG_THRESHOLD = 6         // 位移超过 6px 才判定为拖动
```

## 8. 交互设计（`Bracelet.tsx`）

手串预览区的交互用 **Pointer Events** 实现，同时兼容鼠标与触摸：

- **点按删除**：`pointerdown` 记录起始点；`pointerup` 时若位移未超过 `DRAG_THRESHOLD`（6px），视为点击，删除该珠子。
- **按住拖动排序**：位移超过阈值后进入拖动态（`dragging=true`），珠子放大 `scale(1.2)` 作为视觉反馈；移动时用 `indexAt` 将指针坐标映射到目标槽位，调用 `onMove` 排序。
- **指针捕获**：`setPointerCapture` 确保拖动过程中指针移出珠子后仍能收到事件。

`indexAt` 的坐标→槽位映射与 `beadPositions` 的角度约定保持一致：

```ts
let angle = Math.atan2(clientY - cy, clientX - cx) + Math.PI / 2  // 对齐顶部起点
if (angle < 0) angle += 2 * Math.PI
return Math.round(angle / ((2 * Math.PI) / count)) % count
```

中心区域显示珠子数量（「N 颗」），空手串时显示引导文案「点击下方珠子开始搭配」。

## 9. 移动端适配

- `index.html` 设置 `viewport`：`maximum-scale=1.0, user-scalable=no, viewport-fit=cover`，禁用缩放、适配刘海屏，并设置 `theme-color` 与页面背景一致。
- `App.css` 中 `.app` 使用 `height: 100dvh`（动态视口高度，避免移动端地址栏遮挡）并限制 `max-width: 480px`，桌面浏览时居中显示为手机比例。
- 上下布局：`.bracelet-area` 用 `flex: 1 1 auto` 占据剩余空间，`.palette-area` 固定在下部并限制 `max-height: 46vh`，内部网格 `overflow-y: auto` 可滚动。
- 手串 SVG 尺寸用 `min(74vw, 340px)` 自适应，珠子拖动区域设置 `touch-action: none` 防止浏览器接管手势。

## 10. 本地开发

环境要求：Node.js（CI 中使用 Node 22）与 npm。

```bash
npm install        # 安装依赖
npm run dev        # 启动开发服务器（Vite，默认 http://localhost:5173）
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 本地预览生产构建产物
```

`npm run build` 会先执行 `tsc -b` 做类型检查，再执行 `vite build` 打包。

## 11. 部署（GitHub Pages）

部署由 `.github/workflows/deploy.yml` 自动完成，无需手动操作：

- **触发条件**：推送到 `main` 分支，或手动触发（`workflow_dispatch`）。
- **流程**：`checkout` → 安装 Node 22 → `npm ci` → `npm run build` → 上传 `dist` → 部署到 GitHub Pages。
- **关键配置**：`vite.config.ts` 中 `base: './'` 使用相对路径，确保部署在 `https://<user>.github.io/bead-diy/` 这类子路径下时静态资源仍能正确加载。

> 注意：仓库需在 GitHub 设置中启用 Pages，并将 Source 设为 **GitHub Actions**。

## 12. 代码规范与工程约定

- **换行符**：`.gitattributes` 强制 `* text=auto eol=lf`，避免 Windows 上 CRLF/LF 不一致导致 Git 误报「已修改」；图片、字体等二进制文件不做转换。
- **忽略文件**：`.gitignore` 忽略 `node_modules`、`dist`、`dist-ssr`、`*.local`、`*.tsbuildinfo`、`.DS_Store` 以及 `.history` 目录。
- **TypeScript**：开启 `strict`、`noUnusedLocals`、`noUnusedParameters` 等严格检查，构建时会拦截未使用变量与类型错误。

## 14. 扩展建议

如需继续迭代，建议遵循现有的分层结构：

1. **新增珠子素材**：在 `src/data/beads.ts` 中追加 `BeadType` 条目即可，无需改动组件。
2. **新增分类**：同时向 `categories` 数组与对应珠子的 `category` 字段补充新 id。
3. **接入真实图片/3D**：`BeadGlyph` 是唯一的珠子渲染出口，可在此替换为 `<image>` 或 Three.js 渲染，而不影响上层组件。
4. **价格与清单导出**：`BeadType.price` 字段已预留，可在 `App.tsx` 的状态基础上派生总价与珠子清单。
