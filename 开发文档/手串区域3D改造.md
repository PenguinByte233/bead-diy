# 项目任务：将手串 DIY 页面升级为高真实感的固定俯视角 3D 渲染

## 1. 项目背景

当前项目使用 TypeScript 开发，是一个在线手串 DIY 网页应用。

核心功能包括：
- 用户选择不同类型的珠子。
- 点击珠子材料后添加到手串。
- 手串以完整圆形俯视角展示。
- 用户可以设计自己的珠子排列。
- 后续计划支持保存、分享或发送手串设计给商家。

本次目标：在不破坏现有功能的前提下，升级为具有真实商品展示效果的 3D 手串渲染。

视觉要求：
- 固定俯视角，不需要用户旋转视角。
- 珠子看起来像真实的水晶、玛瑙等圆珠。
- 绳子具有真实材质和厚度。
- 珠子与绳子之间存在合理的遮挡关系。
- 页面保持简洁，移动端能够流畅使用。
- 兼顾开发成本、性能和未来扩展性。

## 3. 技术方案

如果项目使用 React：

- 使用 Three.js 作为 3D 渲染引擎。
- 使用 React Three Fiber 作为 React 集成层。
- 保留 TypeScript 类型约束。
- 采用固定正交相机，实现俯视角展示。
- 优先使用程序生成的球体和绳子几何体，不依赖大量外部 3D 模型。
- 材质、几何体生成和手串业务数据分离。

先检查现有依赖与 React 版本，再选择兼容的稳定版本，不要默认安装 alpha 版本。

不要为了实现本次效果引入过多辅助库。

## 4. 设计数据与渲染层分离

建立或整理统一的手串设计数据结构，至少能够描述：

- 珠子的唯一标识。
- 珠子类型与材质配置。
- 珠子排列顺序。
- 珠子尺寸与颜色。
- 绳子类型。
- 手串整体尺寸和珠子间距。

可以根据现有代码设计 TypeScript 类型，但不要无理由复制一套与现有状态冲突的数据结构。

渲染层根据设计数据计算珠子坐标和绳子路径。

修改珠子数量、顺序、尺寸或绳子类型后，场景应自动更新。

## 5. 珠子的 3D 效果

先使用 SphereGeometry 或适当的球体几何体模拟圆珠。

实现要求：

- 具有圆润的球体轮廓。
- 使用合理的灯光、材质和高光。
- 不同珠子类型能够配置不同颜色、粗糙度、反射和透明度。
- 具有适度的环境明暗变化与接触阴影。
- 避免所有珠子都像塑料玩具。
- 水晶类珠子应尽可能呈现通透感；不透明珠子应以表面高光和颜色层次为主。
- 不要默认对所有珠子使用高成本的物理材质。

请先实现几种代表性材质作为演示，之后再支持扩展更多珠子类型。

## 6. 绳子系统：支持五种材质

建立统一的 CordType 类型：

type CordType =
  | 'transparent-elastic'
  | 'black-elastic'
  | 'brown-braided'
  | 'black-braided'
  | 'burgundy-round';

具体实现根据现有代码结构调整。

### 透明弹力线
- 细线、透明或半透明。
- 使用柔和反光和适当的透明度。
- 避免完全不可见或变成纯白线。

### 黑色弹力线
- 细黑色圆线。
- 具有深灰色层次与柔和高光。
- 与透明弹力线明显区分。

### 棕色编织绳
- 使用棕色纤维纹理。
- 编织纹理沿闭合路径连续分布。
- 不要仅仅通过加粗棕色线条模拟编织。

### 黑色编织绳
- 使用黑灰交错的纹理。
- 与黑色弹力线有明显视觉差异。
- 控制纹理重复频率，避免过于密集。

### 酒红色实心圆绳
- 具有更大的截面半径。
- 使用渐变、高光和阴影体现圆柱体积。
- 呈现柔和的酒红色材质，而不是一条扁平红线。

### 几何体与纹理要求

- 使用连续闭合路径生成圆形绳子。
- 可以评估使用 TubeGeometry 或根据现有项目自行构建闭合管状几何体。
- 对于编织绳，可以使用可平铺纹理或程序化纹理。
- 避免闭合路径接缝处出现明显的纹理错位。
- 绳子应随手串半径和珠子排列变化自动更新。
- 避免不必要地重复创建几何体、材质和纹理。

## 7. 珠子与绳子的遮挡关系

这是本次任务的重点。

- 绳子沿珠子中心排列路径形成完整闭合圆环。
- 绳子应从珠子孔位或珠子之间的缝隙中自然显露。
- 绳子不能像一条线一样直接覆盖在珠子表面。
- 调整珠子和绳子的相对位置、尺寸与渲染关系，避免明显穿模。
- 由于当前采用固定俯视角，可以优先使用适合该视角的几何布局和遮挡方案。
- 不要为了模拟遮挡而手动绘制固定的珠子图片。
- 当用户添加或删除珠子时，遮挡关系必须自动适配。

注意：真实的串珠效果不只是图层前后顺序，还需要合理的珠子中心、孔位方向、绳子路径和尺寸关系。请优先实现视觉正确且容易维护的方案。

## 8. 场景与灯光

- 固定正交相机，完整展示圆形手串。
- 使用柔和的主光、环境光和适度的阴影。
- 背景简洁，突出珠子的颜色和材质。
- 控制曝光与高光，避免珠子过曝。
- 保证手串在不同容器尺寸下不会被裁切。
- 优先考虑移动端性能。
- 不需要添加不必要的旋转控制或复杂动画。

## 9. 与现有 DIY 功能集成

- 保留原有珠子选择区域和操作方式。
- 点击珠子后，现有业务逻辑仍然负责添加珠子。
- 3D 场景读取现有手串设计状态。
- 切换绳子类型时不清空珠子。
- 重新排列珠子后，3D 场景同步更新。
- 保留原有移动端布局：手串显示区域在上，材料选择区域在下。
- 如果现有项目已经实现导出、分享或截图，不要破坏这些功能。

将 3D 渲染组件封装为独立模块，避免业务逻辑直接依赖 Three.js 内部对象。

## 10. 性能与异常处理

- 避免每次状态更新都重新创建整个场景。
- 合理复用几何体、材质和纹理。
- 在不需要透明材质时避免开启额外透明渲染。
- 避免为每颗珠子都单独创建复杂灯光。
- 对 WebGL 不可用或初始化失败的情况提供明确提示；如项目条件允许，可以保留简化的 2D 展示作为降级方案。
- 页面离开时正确释放不再使用的 GPU 资源。
- 不引入没有必要的全局状态管理工具。
